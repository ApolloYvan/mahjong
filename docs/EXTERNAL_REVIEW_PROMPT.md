## 1. 游戏规则（杭州麻将，平台已确认）
- **牌与胡牌**：
  - 136 张牌，白板"白"是财神，可以替代任意牌；
  - **只能自摸，没有点炮**，所以不存在防守放铳；
  - 庄家起手 14 张。
- **吃碰杠**：
  - 吃只能吃上家的牌，每人最多两摊吃；碰、明杠优先于吃；
  - 财神不能吃、碰、杠；
  - 墙剩 20 张以内禁止杠，墙剩 20 张时流局（流局率约 0.3%）。
- **抓打圈**：有人打出财神后，其余三家这一圈只能打刚摸到的牌，并且不能吃、碰、明杠。
- **番型**（乘法叠加）：
  - 平胡 1 番；
  - 七对分支番：七对 2 番、豪华七对更高；
  - 爆头 ×2：听全部牌、摸到任意牌都能胡的形态；
  - 杠开 ×2；连杠、杠飘链 ×2^n；
  - 财飘（爆头态打出财神续飘）每次 ×2，只在最终爆头胡时生效；
  - 4 个白板 ×2：手里的财神加上本人飘出的财神共 4 张。
- **结算（零和）**：
  - 闲家自摸 fan：胡者 +10×fan，庄家 −8×fan，另一闲家 −1×fan；
  - 庄家自摸：胡者 +24×fan，其余每家 −8×fan；
  - 胡者接庄；流局庄家连庄。
- **赛制**：
  - 每场 8 局；
  - 海选 → 16 强（4 组×4 人，组内前 2 晋级）→ 8 强 → 决赛；
  - 排名按 总分 → 名次分 → 财神数。
- **超时**：
  - 出牌思考 3 秒，超时后能胡就自动胡，否则自动打出最右一张；
  - 吃碰窗口各 1 秒，固定走满。

## 2. 硬约束
- **比赛运行环境**：赛方用我们提交的代码运行，**纯 Python 标准库，兼容 3.9**。
  - 不能用 numpy/torch，也不能用 C 扩展；
  - 赛方硬件未知。
- **训练环境**：离线训练可以用 torch，也可以用云主机（有 128 vCPU 的 AMD 抢占式实例，约 5.5 元/小时）。
- **提交体积**：小于 20MB。
- **网络延迟**（实测）：拉取状态 p50 344ms、p99 1.6s；提交动作 p99 95ms。实际可用的计算预算约 1 秒。

## 3. 现状（实测数据）
**最新 30 房实战**（2389 局，对手是真人和其他 AI，包括顶尖玩家）：

| 指标 | 我们 | 高手群体（1.9 万局） |
|---|---|---|
| 分/局 | **−0.02**（95% CI ±0.5） | +1.10 |
| 胜率 | 25.7% | 27.7% |
| 庄家胜率 | 23.8% | 30.0% |
| 庄家每局得分 | −0.05 | +3.12 |
| 平均番数（胡牌时） | 1.37 | 1.45 |
| 4 番以上占胡 | 3.7% | 5.0% |
| 爆头占胡：起手 1 张财神 | 31% | 36% |
| 爆头占胡：起手 2 张以上财神 | 58% | 67% |
| 首次听牌在第几手 / 胡牌在第几手 | 5.26 / 7.81 | 5.24 / 7.84 |
| 吃 / 碰接受率 | 41% / 78% | 41% / 73% |

- **结论**：速度与高手持平；差距在胡牌率、庄家局表现、番数，合计约 **1.1 分/局**。
- **顶尖个体**：同桌数据里，顶尖玩家可达 +1.5 到 +2.2 分/局，但样本有选择偏差。

**现有生产策略**是手工规则加评分，大致包括：
- 向听数与有效进张、按路线（平胡/爆头/七对/七对·爆头）分别估算期望分；
- 弃胡转爆头（S1）：实测净正，116 次触发，84% 最终自摸，比当场胡净多 +1300 分；
- 飘的期望值判断、吃碰门控、杠的门控。
- 与高手决策的一致率：出牌约 80%，吃碰过约 94%。

## 4. 已有的基础设施（都已验证）
1. **规则引擎**：27518 局真实对局逐事件回放，结算、番型、抓打圈、吃碰窗口的不一致数都是 0。
2. **快照构造**：与服务端真实快照比对，105 万个决策点精确对齐，各字段不一致数为 0（语义差别已解释）。
3. **轻量推演引擎**：与规则引擎逐步比对 1 万局，不一致为 0；单局约 3ms（M5 性能核）。
4. **对手模型**：贪心策略加胡牌率补足，按高手实测校准：第 6/10/14 摸累计胡牌率、2 番以上占比都在 3pp 以内。
5. **同牌 A/B 对战平台**：轮座、镜像、按种子聚类的置信区间，可以按座位设置不同开关；目前对手是我们自己的 bot。
6. **数据**：约 3800 个对局文件、2.7 万局我方对局，另有其他玩家的大量对局；能采集我方参与过的房间。
