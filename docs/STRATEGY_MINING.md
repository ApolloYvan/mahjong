# 从高手对局逆向工程情境策略：方法设计

> 目标：16 天内找到能让分/局从 +0.17 提到 +0.91（前十线）的**情境规则**。
> 约束：纯标准库（无 numpy/pandas/sklearn）；一房 ≈15 分钟、只能串行，10 房一个实验 ≈2.5 小时。

---

## 〇、六条设计原则（每条都是 2026-09-24 实际踩出来的）

| # | 原则 | 反例（踩过的坑） |
|---|---|---|
| P1 | **用结果判优劣，不用我们自己的特征判优劣** | 「他在最大化什么」探针里，进张列对任何偏离我们 argmax 的选择都显示为负——我们自己的历史弃牌也是 −1.54。用自家评分函数的特征去评价别人，结论必然偏向自家 |
| P2 | **只用全语料，禁用精选回放做结论** | `data/replay.jsonl` 14/14 显示「合计推到 4 再胡」，全语料证明等待 EV 只有立刻胡的 1/36 |
| P3 | **状态只含决策当下可见的信息** | events 里有四家起手牌，直接当特征用 = 信息泄漏，学出来的规则上线必失效 |
| P4 | **先扣噪声地板** | 我们自己的历史弃牌 vs 当前代码一致率 95.2%，4.8% 是版本漂移；分歧率要减去它才是信号 |
| P5 | **规则必须跨 ≥2 名高手成立，且在留出集复现** | 单人行为可能是风格，不是优势 |
| P6 | **实战一次一条、预先登记判据、核实 build_hash** | 三个改动叠在一起分不清；留白溢价实验第一房是改动前开打的 |

## 一、状态编码（每个决策点一行）

决策点 = 本方每一次 `弃牌` / `吃碰杠响应` / `可胡时的胡或飘`。

### 1.1 身份与时点
| 字段 | 说明 |
|---|---|
| `game_id, round_no, seq, seat, uid` | 定位 |
| `cohort` | top / ours / bottom（按 ≥150 局的分/局分位） |
| `is_dealer` | 庄闲——赔付不对称：庄胡收 24×，闲胡收 10×（其中庄付 8×）|
| `turn_no` | 本方第几巡 |
| `wall_left` | 墙剩余张数；派生 `to_dead = wall_left − 20`（距最后 10 墩）|

### 1.2 本方手牌（只用自己的）
| 字段 | 说明 |
|---|---|
| `shanten_std / shanten_7p / shanten_route` | 平胡 / 七对 / 组合向听 |
| `ukeire, ukeire_live` | 进张种数 / 按可见张数加权的活张 |
| `wait_cover` | 听口覆盖张数/34（`joker_ev.hand_wait_cover`），爆头 = 34 |
| `to_baotou` | 去掉 1 张财神后「全部做成完整面子」还差几步（**爆头专用距离**，新写）|
| `jokers, pairs, triplets, lone` | 手中白数 / 对子 / 刻子 / 孤张 |
| `melds, chi_used` | 副露组数 / 已吃摊数（上限 2）|
| `chain, piao_out, joker_total` | 链次数 / 已飘出白 / 手中白+已飘（4 白板判据）|

### 1.3 牌桌（公开信息）
| 字段 | 说明 |
|---|---|
| `opp_melds_max, opp_melds_sum` | 对手副露——对手接近听牌的公开代理 |
| `dealer_melds` | 庄家的副露数（闲家视角最危险的人）|
| `catch_play, i_am_exempt` | 抓打圈是否进行中 / 我是否豁免方 |
| `visible_joker` | 已现白板张数（决定还能摸到几张白）|
| `opp_tenpai_p[3]` | 三家对手的听牌概率估计（见 1.6，H1 专用）|

### 1.6 对手听牌估计器（用全明牌回放校准）
注意：本规则**只能自摸、没有点炮**，传统麻将里对手建模的主要用途（防守、避免放铳）在这里不存在；它只在 H1（冻结谁）真正有用。
- 训练：events 里有四家完整手牌 → 标签 = 对手**真实**向听 ≤0；特征只用公开信息（对手副露数/类型、巡数、弃牌里的字牌与幺九比例、最近 3 巡是否摸切）
- 模型：手写逻辑回归或分桶频率表，按房间留出 30% 评估校准度
- **只作为状态特征，不把真实手牌带进任何决策特征（P3）**

### 1.4 场况（领先落后）
| 字段 | 说明 |
|---|---|
| `sess_score, sess_rank` | 本场（同 4 人 8 局）累计分与名次 |
| `gap_to_1st, gap_to_4th` | 与第一 / 第四的分差 |
| `rounds_left` | 本场剩余局数 |

### 1.5 动作与结果标签（结果只做标签，**绝不进特征**）
| 字段 | 说明 |
|---|---|
| `act_type, act_tile, act_cat` | 动作；牌类别 字/幺九/二八/中张/白 |
| `our_policy_act` | 当前代码在同一状态会做什么（反事实）|
| `tier_gap` | 他的弃牌比最快层慢几步（已知 95% 在层内）|
| `y_hu, y_fan, y_score` | 本局是否自摸 / 番数 / 本局得分 |
| `y_bt` | 本局是否到达过爆头 |
| `y_tenpai_k` | k 巡内是否听牌（低方差中间结果）|
| `y_opp_hu_k` | k 巡内是否有对手胡（控场类假设专用）|

**实现**：`tools/decision_table.py` 把 1238 个 events 文件重放成一张 CSV（stdlib `csv`）。后面所有分析只读这张表。**这是最容易出错的一步**（重放、信息泄漏），要单独写测试：随机抽 20 个决策点，人工核对手牌与公开信息。

## 二、分歧点挖掘

### 2.1 三个对照组
| 对照 | 用途 |
|---|---|
| A. 高手真实动作 vs **我们的真实动作**（同情境桶）| 行为率差：他们在这种局面下更常做什么 |
| B. 高手真实动作 vs **当前代码的反事实动作**（同一状态）| 具体到手：哪一手我们会打错 |
| C. 高手 vs 垫底玩家 | 排除"只是风格"：若垫底也这么做，就不是优势 |

### 2.2 情境桶（精确匹配）
```
bucket = (is_dealer, shanten_route 0/1/2/3+, melds 0/1/2+, jokers 0/1/2+,
          wall 段 [>60, 40-60, 20-40], chain>0, catch_play, sess_rank 段)
```
约 2×4×3×3×3×2×2×2 = 1728 桶。高手决策点约 5 万个，精确桶平均不到 30 且严重偏向常见局面——**稀有但高价值的情境（尾段、链中）会被整个丢掉。**

**分层回退**：两组都 ≥30 才用精确桶；不足则按 `sess_rank → catch_play → chain → wall 段` 的顺序逐个丢维度合并，直到够样本。每条结论标注它用的是第几层桶。

### 2.2b 局面覆盖率（先于一切优先级排序）
高手数据里的局面是高手自己打出来的，**我们的程序未必遇得到**。对每个候选桶/规则：
```
coverage = 我们历史决策点落在该桶的比例
预期收益 = Δ（2.4）× coverage
```
**按预期收益排序，不按 Δ 排序。** Δ 很大但覆盖率 <1% 的规则，上线后几乎不触发，推后。

### 2.3 行为率比较
- 每桶每个动作类别：两比例 z 检验
- **多重比较用 Benjamini-Hochberg 控 FDR 到 5%**（几千个检验，不校正必然"发现"一堆假规律）
- 减去噪声地板：分歧率 ≤ 5% 的桶直接丢弃

### 2.4 期望得分差（核心，决定一条规律是否值得学）
**不用我们的评分函数判断哪个动作好（P1），用结果：**
```
同一桶内，按动作分组（不分人，全体玩家混合）
Δ = mean(y | 高手常做的动作) − mean(y | 我们常做的动作)
```
- **分层汇总**：各桶 Δ 按 min(n_a, n_b) 加权（Mantel-Haenszel 式），不跨桶混合
- **聚类自助法求 CI**：按**房间**重采样 1000 次——同一房的决策高度相关，按决策点重采样会把 CI 算窄（伪重复）
- **y 的选择**：`y_score` 方差太大；优先用 `y_tenpai_k / y_bt / y_hu` 这类低方差中间结果，再用价值模型换算成分/局：胜率 +1pp = +0.231，番/胡 +0.1 = +0.272
  - **来源**：46 名 ≥250 局玩家的横截面回归 `分/局 = −9.274 + 23.111×胜率 + 2.721×番/胡`，R²=0.907
  - **局限**：这是跨玩家的相关关系，不是因果。只用来给中间结果换算量级；**最终入选仍以 `y_score` 的聚类 CI 为准**
  - 一阶校核：收入/局 ≈ 胜率 × 番/胡 × 平均每番赔付（庄 24、闲 10，按 1:3 加权约 13.5）；胜率系数比这个大，是因为零和——我们多胡一次，对手就少胡一次、我们少付一次
- **选择偏差（手牌）**：做某动作的人本来就可能手更好。缓解：桶内再按 `ukeire`、`wait_cover` 分三档，档内比较
- **选择偏差（技术水平）——更严重**：若动作 A 大多是高手在做，A 组结果好可能只是「做 A 的人后面打得也好」。**主比较改为同一人内部比**：同一名玩家在同一桶里有时做 A、有时做 B，只比这些样本。跨人混合比较只作为辅助

## 三、规则提取

输入：通过 2.3 + 2.4 的分歧桶里的决策点。标签 = 「高手动作类别 ≠ 我们反事实动作」的具体方向。

| 方法 | 做法 | 产出 |
|---|---|---|
| **浅层决策树** | 手写 CART，深度 ≤4，叶子 ≥200 样本，Gini 分裂 | 每个叶子 = 一条 `IF … THEN 高手 X% 做 A，我们 Y%` |
| **规则挖掘** | 离散化特征后枚举 ≤3 个条件的合取，按 support ≥100、lift ≥1.5 过滤 | 覆盖树漏掉的交互 |
| **聚类** | 分歧点按标准化特征做 k-medoids（纯 Python，k=6~10）| 每簇 = 一个"套路场景"，用簇中心描述 |

**入选条件（全部满足）**：
1. 2.4 的 Δ 的 95% CI 下界 > 0
2. 在 ≥2 名高手身上方向一致（P5）
3. 垫底玩家不这么做（对照 C）
4. 70% 房间上挖出、30% 留出房间上复现
5. 能写成一条 ≤3 个条件的 `if` 语句

## 四、可验证的高手套路假设

每条写明：可测定义 → 用哪些字段 → 离线通过标准。

### H1 打财神控场（非爆头态主动打白，冻结对手一圈）
- **依据**：规则明文「打出财神那一圈，其余玩家不能吃碰明杠、出牌只能打刚摸到的牌」。这是唯一能干预对手的工具。我们有 `discard_joker_soft = −800`，非飘不打白。全平台 295 次弃白里只有 62 次是真财飘——**另外 233 次是谁在什么情况下打的？**
- **定义**：`act_tile=白 且 非爆头`
- **先验证机制**：events 里非爆头弃白后 `catch_play` 是否为 true
- **通过**：高手在 `opp_melds_max≥2`（或 `dealer_melds≥2` 且我是闲）时该率显著高于我们，且 `y_opp_hu_k`（k=4）显著更低

### H2 庄闲分离
- **依据**：赔付不对称——闲家胡时庄家独付 8×，另两闲各付 1×。**庄家怕任何人胡，闲家只怕庄家胡。** 我们的代码却是 `is_dealer → use_route=True + dealer_hint`，庄家反而走慢的爆头路线。`dealer_edge` 已测到：我们坐庄胡率 30.6% 高于对手 28.6%，庄位分/局却只有对手的 0.67 倍
- **定义**：分庄闲比较 胡牌巡数、番/胡、首次听牌巡数
- **通过**：高手庄/闲的「速度 vs 番数」取舍方向与我们相反或幅度显著不同，且按庄闲分层后 Δ>0

### H3 最后 10 墩提前量
- **依据**：最后 20 张不摸、最后 10 墩禁杠、流局庄家连庄
- **定义**：按 `to_dead` 分段，看高手何时从大牌路线（七对/留白/`joker_plan`）切到最快听牌
- **通过**：存在一个切换点（如 `to_dead<15`），高手在其后的「放弃留白」率跳升而我们没有；该段 `y_hu` 高手显著更高。庄家另看：尾段是否倾向保流局（连庄）

### H4 爆头摸白板：胡还是飘（情境化）
- **依据**：已知「打后仍爆头」单步成功 91.3%，但我们的决策只看 EV，不看庄闲 / 剩余墙 / 场况
- **定义**：`状态=爆头 且 摸白` 时 `act=hu` vs `act=discard 白`
- **通过**：按 (`is_dealer`, `wall_left` 段, `sess_rank`) 分层，每层算 **Δ = E[y | 飘] − E[y | 胡]**（同人内部比），找出 Δ 的 CI 与我们现行判据给出的选择相反的层。**只看比例变化不算数**——高手在某层习惯性地飘，不等于飘在那层更好

### H5 弃胡（非爆头可胡时放弃）
- **依据**：规则允许弃胡；「合计推到 4」已证伪，但**其他形态的弃胡**没查过（如手里有白、离爆头只差一步时放弃 1 番平胡）
- **定义**：本方摸到能胡的牌却打出（需在重放里判胡）
- **先验证存在性**：高手的弃胡率是否显著 > 0。若 ≈0，直接关掉此方向
- **通过**：弃胡组本局 `y_fan×y_hu` 的均值 > 立刻胡的番，按房间聚类 CI 下界 > 0

### H6 领先落后切换
- **依据**：同 4 人连打 8 局，我们对场况零感知
- **注意**：晋级排名首键是**总分**，名次分只做并列裁决——所以方差策略的价值可能很小，**优先级最低**
- **定义**：按 (`sess_rank`, `rounds_left`) 分组看飘的比例、七对路线比例、番/胡
- **通过**：领先方降方差、落后且 `rounds_left≤2` 时升方差，且方向在 ≥2 名高手一致

### H7 首副露的选择性（非指定方向，但证据最强）
- **依据**：`score_attribution` 显示我们 1 露收入占比 28%（全场最低）、2 露 57%（全场最高）；高手 1/2 露均衡
- **定义**：第一次吃碰窗口的吃碰率与吃碰后 `wait_cover` 增量
- **通过**：高手首副露更挑剔，且其首副露后 `y_tenpai_k` 显著更高

## 五、验证方案

### 5.1 离线（便宜，先筛掉大部分）
第二、三节的全部入选条件。**没过离线的假设不进实战。**

### 5.2 实战 A/B
| 项 | 规定 |
|---|---|
| 粒度 | 一次只开一条规则，挂在独立开关上 |
| 登记 | 开跑前把 假设 / 主指标 / 阈值 / 房数 写进 `docs/experiments/Hx.md` |
| 核实生效 | 每房检查决策日志的 `build_hash` 与开关状态（P6）|
| **主指标** | **机制指标**，不是分数。例：H1 = 非飘弃白率 + 其后 4 巡对手胡率；H2 = 庄家听牌巡数 |
| 护栏 | 胜率跌幅 ≤0.94pp（价值模型的盈亏平衡点）；代打 ≤0.2% |
| 分/局 | 只报告不判定——10 房的标准误 ±0.76，看不出 0.74 的差 |
| 房数 | 机制指标 10 房；最终组合版本跑 30 房看分/局 |

### 5.3 区分运气与策略
1. **机制指标** 由策略直接控制、方差低，不受牌运主导
2. **起手质量协变量调整**：用起手向听、起手财神数、庄闲做回归调整（CUPED 式），能显著缩小分/局的方差
3. **对手强度调整**：`head_to_head` 同一批对手前后比；或按同桌对手的历史分/局加权
4. **按房间聚类**算 CI，不按局或决策点
5. **预先登记停止规则**：主指标 10 房无迹象即停（留白溢价就是这么停的）
