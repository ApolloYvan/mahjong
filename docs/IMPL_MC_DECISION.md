# 阶段二：蒙特卡洛模拟决策（mj/mc/）

## 0. 目标与原则

**项目目标**：每次决策选"本局期望得分 + 连庄价值"最大的动作。
- 牌好时冲大番，对手快时转快胡，每摸一张、打一张都重新计算。
- 本阶段的做法：把每个候选动作放到同一批"随机补全隐藏牌"的牌局上，模拟打完本局，比较各候选的平均得分。

**原则**：
- 生产逻辑负责给出候选和兜底，模拟只在候选之间裁决。
- 只有当模拟以足够把握认为另一个动作更好时，才推翻生产逻辑的选择（§5）。
- 时间不够或出现任何异常，一律退回生产逻辑的选择。
- 默认关闭，由开关控制。
- 上线与否只看 arena2 的 A/B 置信区间。

**工作规则**：同 `docs/IMPL_PHASE1_WRAP.md` §0。
- 不跑长任务；运行前用退出码卡住 bot 检查；
- 用户跑批量期间不改会被 import 的文件；
- 长任务写成一条命令交给用户，汇总不超过 40 行。

**运行约束**：
- 纯标准库，兼容 Python 3.9。赛方用未知硬件运行我们的代码。
- 出牌时限 3 秒，超时会自动打出最右一张牌。
- 碰、吃窗口各 1 秒，固定走满。

## 1. 模块

| 文件 | 内容 |
|---|---|
| `mj/mc/fast.py` | 查表判胡与离胡距离。标准胡（含副露组数）、七对、爆头；按花色分解，每门 9 位计数为 key，字牌单独处理，财神作通配；惰性缓存，不落盘或落盘 <5MB |
| `mj/mc/determinize.py` | 按可见信息随机补全隐藏牌 |
| `mj/mc/rollout.py` | 轻量推演状态（计数数组，不用 `deepcopy(RoundEngine)`）和四家快速策略 |
| `mj/mc/decide.py` | 候选生成、共用随机牌局（CRN）、逐轮淘汰、预算、推翻规则、日志 |
| `tests/test_mc_*.py` | 单元测试 |
| `tools/mc_check.py` | 正确性、校准、测速的长任务（用户执行） |

## 2. 规则一致性（必须和 G1 引擎完全一致）

推演中的胡牌判定与计番，必须复用与 `mj/sim/engine.py` 相同的口径：
- `mj.rules.evaluate`；
- 连杠、杠飘链、"财飘只在爆头胡时生效"、4 个白板（手里的财神 + 本人飘出的财神 = 4）、杠开；
- 流局点：服务端口径墙剩 20 张（引擎口径 21）；
- 禁杠阈值；抓打圈；每人两摊吃上限；财神不可吃、碰、杠。

建议把引擎里的计番、结算逻辑抽成纯函数，供两边共用。但必须等用户的阶段一批量跑完才能改 `mj/sim/`，改完要重跑事件回放，确认仍然零不一致。

**验收**：`tools/mc_check.py equiv`：
- 随机生成 1 万局完整对局，推演状态和 `RoundEngine` 逐局比对胜者、番数、得分，不一致 = 0；
- `fast.py` 与 `mj.rules`、`mj.shanten` 在 100 万手随机牌（0–4 张财神、0–4 组副露）上逐一比对，不一致 = 0。

## 3. 隐藏牌补全

- **未见牌** = 136 张 − 自己的手牌 − 所有弃牌 − 所有明示副露。暗杠是否可见，以快照为准。
- 各对手的手牌张数由副露数决定。
- 其余未见牌洗成牌墙，**张数必须等于快照的 `wall_remaining`**（服务端口径）。
- 第一版用均匀随机，不做读牌。
- **读牌钩子**：预留按对手弃牌给补全加权的接口，本轮不启用。

## 4. 推演策略

**对手（快速贪心）**：
- 出牌：打出使离胡距离（标准胡与七对取较小者）最小的牌；平局时比较有效进张，再比较孤张程度。
- 吃碰：距离能减少时才吃碰，并遵守两摊吃上限和抓打圈。
- 胡牌：能胡就胡。
- 飘：处于爆头态并摸到财神时，按一个概率飘。
- **可调参数**：吃碰激进度、出牌随机扰动、飘的概率。这些参数由 `tools/mc_check.py calibrate` 拟合，使推演对手的胡牌曲线和番数分布对齐 `reports/sim_calibrate.json` 中的**高手**数据。
- 验收：累计胡牌率在第 6、10、14 摸的误差都在 ±3 个百分点以内；2 番以上占胡比例的误差在 ±3 个百分点以内。

**我方（按路线固定目标）**：对每个候选动作，分别按四条路线推演：
- R_A：普通胡，只看速度，能胡就胡；
- R_B：爆头，保留财神；在墙剩余低于阈值之前只接受爆头胡，之后什么都胡；飘的规则同生产代码的简化版；
- R_C：七对；
- R_D：七对·爆头。

没有财神的手只推演 R_A 和 R_C。

**候选动作的价值** = 各路线平均值中的最大者。所有候选、所有路线共用同一批补全牌局。

**单次推演的价值**：
- 我方本局得分增量（按真实支付规则）；
- 如果我方胡牌，再加上连庄价值 `V(round_no)`。
  - 取值来自 `models/dealer_value.json`，自己读，不依赖 `rev_dealer_value_enabled` 开关。
  - 第 8 局的 V = 0。

## 5. 决策流程（`decide.py`）

**范围（每项一个开关，默认都是 0）**：

| 开关 | 管的决策 | 候选 |
|---|---|---|
| `mc_hu_enabled` | 胡、飘、弃胡（`choose_hu_or_piao` 的决策） | 胡、飘、弃胡之后打哪张（取生产逻辑排名前 2） |
| `mc_discard_enabled` | 普通出牌 | 生产评分的前 3 名，必须包含生产逻辑本来的选择 |
| `mc_claim_enabled` | 吃、碰、过（第二优先级，时间不够可以不做） | 吃、碰、过 |

**流程**：
1. **预算**：`deadline = t_snapshot_received + min(cap, 3.0 − latency_est − margin)`。
   - `cap`：出牌、胡飘各 1.5 秒；吃碰 0.3 秒。
   - `latency_est` 和 `margin` 使用阶段一时间链实测给出的常数，写在 weights 里，可以调整。
2. **逐轮淘汰**：每轮给每个存活的候选各跑 16 局补全牌局。每轮结束后，淘汰那些"均值 + 2×SE < 当前最好候选的均值"的候选。到截止时间立即停止。
3. **推翻规则**：只有同时满足以下两条，才采用模拟选出的最优动作，否则用生产逻辑的选择：
   - 最优候选与生产选择的配对差（两者用同一批补全牌局）> `mc_z` × 配对差的标准误。`mc_z` 默认 1.0。
   - 每个候选都跑到了至少 `mc_min_n`（默认 64）局。
4. **兜底**：任何异常、时间不够，或推演次数没达到 `mc_min_n`，都返回生产逻辑的选择。
5. **日志**：写进 decision 事件，内容包括：候选、各候选均值、标准误、推演局数、选中的路线、耗时、是否推翻了生产选择、兜底原因。

**接入方式**：
- 在 `mj/bot.py::choose_action` 算出生产结果之后调用 `mc_override(snapshot, action, rules)`。
- 各开关为 0 时，行为必须逐字节不变，用测试证明。

**arena 模式**：
- 对战平台里不按时间停，而是固定推演次数（`mc_fixed_n`，默认 128）。
- 随机种子由对局种子和决策序号推出，保证结果可以复现。

## 6. 验收（全部由用户执行一条命令 `bash tools/phase2_batch.sh`）

| 关卡 | 标准 |
|---|---|
| 1. 规则一致 | §2 的两项不一致 = 0 |
| 2. 校准 | §4 对手推演的误差在范围内；汇总表里给出拟合出的参数 |
| 3. 速度 | 能效核单进程下：出牌决策的中位数，要能在 1.5 秒内让 3 个候选各跑够 128 局；决策耗时的 p99 不超过预算 50 毫秒以上；报告兜底率 |
| 4. arena | A = 模拟决策开，B = 当前配置。以 1v3 布局为主、2v2 为辅，分三组：只开胡飘、只开出牌、两者都开。**过关：A−B 的 95% 置信区间整体大于 0**。同时报告爆头率、平均番数、4 番以上占比的变化 |
| 5. 实战冒烟 | 只在第 4 关通过之后进行。用户跑 2 房：由计算导致的超时 = 0 |

**arena 局数**：按 1v3 布局下"±0.5 分/局"的分辨率来估算。耗时控制在 4 小时以内，如果超出，降低 `mc_fixed_n` 并在报告中说明。

## 7. 时间表与兜底

- 10/3 前完成实现和单元测试，交出 `phase2_batch.sh`；10/4 用户执行，然后裁决。
- 某个开关没过第 4 关，就保持 0，按当前配置提交。
- 不做（留作后续）：对手回合时提前计算、读牌、阶段末按晋级概率决策（C2）。模拟给出的是每个动作的得分分布，C2 以后可以直接用它来算晋级概率。
