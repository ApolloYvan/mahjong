## 2. arena2 补完（`tools/arena2.py`）

现有的 `aa` 子命令只检查"同一配置四家各座位的均分"，**不是**我们需要的 A/B 配对检验。
另外 `_config_scores` 用 `id(overlay)` 区分配置，两份内容相同的配置会互相混淆。要补以下内容：

1. **新增 `ab` 子命令**：
   - `--a A.json --b B.json`：权重覆盖文件，空文件或 `{}` 表示当前配置。
   - 另外有 `--matches N --jobs K --seed S --layout {2v2,1v3}`。
2. **两种座位布局**：
   - `2v2`：AABB 在 4 个座位上共有 6 种排法，每个种子全部跑一遍。
   - `1v3`：A 分别坐 4 个座位各跑一遍，另外 3 席是 B。这个布局对应比赛里"我们 1 家对 3 家"的真实局面。
   - 配置按显式的标签（"A"/"B"）区分，不再用 `id()`。
3. **同牌**：同一个种子的所有排法都使用相同的每局牌墙（沿用 `seed*1000+round_no` 的约定）。
4. **统计**：
   - 以种子为单位计算配对差 = A 每局均分 − B 每局均分，给出均值和按种子聚类的 95% 置信区间。
   - 同时给出：每房第一名率之差、胜率、平均番数、爆头/七对/财飘/杠开占胡的比例（分 A、B 两列）。
   - 非法动作计数，按动作类型分列。
5. **缓存续跑**：按种子写入 `tools/.cache/arena2/`，重跑时跳过已完成的种子。
6. **A/A 检验**：用 `ab` 子命令、A 和 B 都是当前配置来跑。
   - 验收：置信区间包含 0。
   - 报告置信区间的半宽，以及达到 ±0.3、±0.5 分/局分辨率各需要多少局、在 8 进程下要跑多久。
   - 旧的 `aa` 子命令可以保留，但要改名为 `seatbias`。
7. **测速 `bench`**：
   - 单核跑 60 秒；再用 `taskpolicy -c background` 在能效核上跑 60 秒。
   - 报告每核每小时局数，以及每一步决策的耗时 p50/p99。

## 3. G3a 模拟器校准（`tools/sim_calibrate.py`）

**对比三组**：
- arena2 自对局（A/A 的明细就能用，arena2 要记录每局所需的字段）；
- 真实日志里的高手；
- 真实日志里的我方。

**口径**：
- 按摸牌序号的胡牌率和累计胡牌率，分庄/闲，分胡牌时副露 0/1/2+；
- 番数分布（1/2/4/8/16+）；
- 爆头、七对、财飘、杠开、4 个白板占胡的比例；
- 每局吃、碰、杠的平均次数；
- 流局率。

每项附 n 和 95% 置信区间。

**用途**：这张表是阶段二对手模型的校准标靶，所以明细要写成机器可读的 `reports/sim_calibrate.json`。

## 4. G3b 差距分解（扩展现有的 `tools/gap_breakdown.py`，不要另起炉灶）

- **防选择偏差**：按 `md5(room_id)` 的奇偶把房间分成两半。
  - 一半用来按成绩选高手；
  - 另一半用来做差距分解；
  - 两种切分方向都报告。
- **分解项**：胡得少 / 胡得小 / 输得多，外加做庄。按"起手财神数 × 副露数"分格，每格附按房间聚类的 bootstrap 置信区间。
- **对账**：各项之和必须等于总分差，误差小于 0.01 分/局。
