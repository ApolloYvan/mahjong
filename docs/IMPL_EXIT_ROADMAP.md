# 冲击顶尖：专家迭代（Expert Iteration）路线图

## 0. 目标与已知事实

**目标**：拿到每一局能拿的所有分，最终超过顶尖高手。
- 动态权衡大番和快胡，并按对手速度调整。

**已知事实**：
1. 当前生产策略已与高手群体持平：
   - 离线 MC 遗憾值与高手同一量级；
   - 去掉选择偏差后，差距分解不显著。
2. 再模仿高手，上限就是高手水平；要超过高手，只能靠策略改进。
3. 实时 MC 失败，原因有两个：
   - 推演中我方后续由弱贪心策略接手，估值有偏；
   - 推翻门槛 z=1 太松。
   - 结果：全开 −0.24，只开胡飘 −0.10。
4. 已有的资产：
   - 与服务端 100% 一致的规则引擎，以及推演状态 slim（1 万局逐步比对，0 不一致）；
   - 按高手速度校准的对手模型；
   - arena2 同牌 A/B。

**路线**：神经网络策略加上搜索改进，交替迭代（专家迭代，ExIt）。
- **搜索**：以当前策略为基础做 rollout，得到比当前策略更好的动作。这是单步策略改进，有理论保证。
- **网络**：学习搜索给出的改进动作，并把它压缩成实战里够快的策略。
- **迭代**：新网络成为下一轮搜索的基础策略。每一轮都必须在 arena 上通过 1v3 A/B（95% CI > 0）才能采纳。

## 1. 硬约束

1. **实战运行时**：纯 Python 标准库，兼容 3.9，赛方机器未知；出牌时限 3s，吃碰窗口 1s。
   - 网络推理用纯 Python 实现；
   - **能效核上单次推理 ≤50ms**；
   - 超时或异常一律回落到生产策略。
2. **训练环境不受限**：可以用 torch，可以上云主机或 GPU。训练代码放在 `tools/train/`，**不能被 `mj/` 下的任何文件 import**。
3. **提交体积 <20MB**：网络权重存成 JSON 或 base64，控制在 5MB 以内。
4. **工作规则**：
   - 超过 1 分钟的命令交给用户执行；
   - 运行前用退出码卡住 bot 检查；
   - 每个批量提供 `--smoke` 模式，你自己先跑通；
   - 每一步都有 `--max-minutes` 和缓存续跑；
   - 汇总不超过 40 行；
   - 默认 `MJ_JOBS=6`，命令前加 `caffeinate`、`nice`。
5. 不改 `models/weights.json`。所有新策略都用开关接入，开关默认 0。

## 2. 阶段与关卡（每一关不过，不进下一关）

### S1 状态编码与数据集
- **`mj/nn/encode.py`**（纯标准库，实战也要用）：把生产快照编码成定长特征。
  - 内容：自己手牌的 34 维计数、财神数、四家副露、四家弃牌（计数加最近 6 张）、墙剩余、庄家、局号、四家分数、抓打圈状态、链数、本座位飘过的财神数、可见牌计数。
  - 动作空间：出牌 34 维；胡/飘/弃胡；吃（3 种）、碰、杠、过。
- **`tools/train/build_dataset.py`**：
  - 数据来源：真实日志，所有玩家、所有决策，标签是实际动作，附带本局结果；以及 arena 自对局。
  - 用法：按房间切分训练集和验证集。
  - 验收：编码器在 1 万个真实快照上，与生产快照逐字段一致，并且可逆字段可以还原。

### S2 模仿基线（网络起点）
- **训练**：策略网络分出牌、吃碰、胡飘三个头，同时训练一个价值网络（预测本局得分加连庄价值）。
- **训练数据**：以高手为主。高手名单按房间哈希的一半来选，避免选择偏差。
- **验收**：
  - 验证集 top-1 一致率不低于现有 `mj/nn_discard.py` 和生产策略；
  - 纯 Python 推理与 torch 前向的最大绝对差 <1e-5；
  - 能效核单次推理 ≤50ms；
  - **arena 1v3，网络策略对生产策略，95% CI 不显著为负。** 模仿基线允许和生产策略持平；它的作用是给迭代提供一个快速、可微的起点。

### S3 搜索改进器（专家）
- **推演**：每一轮的基础策略是当前网络（训练时用 torch 批量推理），对手在两种模式之间按比例混合：
  - 高手校准的 slim 加胡牌率补足；
  - 当前网络或生产策略。
- **候选**：网络给出的前 K 个动作，所有候选共用同一批补全牌局（CRN），逐轮淘汰；选择与检验使用独立的两批牌局，z≥2 才算改进。
- **价值网络**：用来截断推演，不必推演到局终，以提速；必须验证截断前后的估值偏差。
- **验收**：在 arena 上，"网络 + 实时单步搜索（只用于离线评测，不限时）"的策略对"网络"本身，CI > 0。这证明专家确实比基础策略强。

### S4 迭代（ExIt 主循环）
**一轮的流程**：
1. arena 自对局，加上真实日志采样，得到状态；
2. 专家对这些状态给出改进动作分布；
3. 网络学习这些改进动作（交叉熵）；价值网络学习推演回报；
4. arena 1v3：新网络对当前最优，CI > 0 就采纳，成为新的最优。

**防止过拟合自身**：对手池包括 历代网络、生产策略、高手模仿网络、高手校准的 slim。arena 评测时同时报告对各类对手的结果。

**算力**：S4 允许在云主机上跑（纯标准库加 torch）。文档要写明需要拷贝的文件，**不含令牌**。

### S5 实战接入
- 网络推理接入 `mj/bot.py`，开关 `nn_policy_enabled`，默认 0。
- 可选：在剩余时间预算内，用价值网络做 1 步搜索。
- 硬时限，回落到生产策略。
- **验收**：
  - 用 speed-live 在真实快照上测量：能效核 p99 ≤ 300ms，回落率 <1%；
  - 实战冒烟 2–3 房：零超时，零 409 增量。

### S6 积分形势层
- 把"本阶段剩余局数、各家累计分、晋级线"加入特征。
- 末段的奖励改为晋级概率，不再是分数。
- 在 arena 里模拟赛制（小组 4 人、前 2 晋级）来评测：晋级率的 CI > 0。

## 3. 每轮交付格式

- 一条命令（批量脚本）、预计耗时、你自己的 smoke 输出；
- 用户执行后贴回 ≤40 行汇总；
- 汇总必须包含 arena 的 A−B 均值、CI、种子数，以及胡牌率、平均番数、爆头/4 番以上占比，与高手指标对照。
