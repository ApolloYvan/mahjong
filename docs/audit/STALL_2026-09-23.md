# 整进程停滞：`socket.timeout` 不是 `TimeoutError`（Python 3.9）

日期：2026-09-23。影响：**一小时的连续对战里，6 个房间报废 2 个。**
优先级高于任何策略改动。

## 1. 现象

用户连续跑了 6 个自由对战房。按 events 统计我方实际行为：

| 房间 | 局 | 胜 | response 超时 | **discard 超时** | **我方弃牌中由服务端代打** |
|---|---|---|---|---|---|
| a_cb28f1b32117 | 79 | 26 | 237 | 1 | **0%** |
| a_6b3bcfc349dd | 78 | 22 | 232 | 1 | 0% |
| a_fad8b7a9f04a | 80 | 14 | 362 | 2 | 0% |
| a_9cffd9377e9c | 79 | 22 | 563 | 45 | 5% |
| **a_ab6382643ee5** | 76 | **3** | 2666 | **675** | **69%** |
| **a_e2eb6e654532** | 78 | **1** | 2975 | **738** | **73%** |

**后两个房里七成的牌是服务端超时后替我们打的。** 那不是打输，是弃权。

决策日志里对应四次整进程停滞（期间 10 个线程一条记录都没写）：

```
04:44:44 → 05:01:22   997 秒
05:05:52 → 05:17:08   676 秒
05:18:09 → 05:33:09   899 秒
05:33:55 → 05:48:54   899 秒
```

同一张桌的前后两条请求直接证明牌局在我们缺席时推进：

```
05:18:09  state  b6桌  requested_seq=0 → returned_seq=22
     ...静默 15 分钟...
05:33:09  state  b6桌  requested_seq=0 → returned_seq=1664
```

停滞结束时游戏往往已经消失：`HTTP 404 GAME_NOT_FOUND` 共 80 次。

排除项：日志丢弃（该时段无任何 drop/queue/overflow 记录），所以不是"日志写线程挂了、
bot 其实在打"——events 独立确认我们确实没在打。

## 2. 根因

```
Python 3.9.6
socket.timeout is TimeoutError ?          False
issubclass(socket.timeout, TimeoutError)? False
issubclass(socket.timeout, OSError) ?     True
```

`socket.timeout` 从 **Python 3.10** 起才成为 `TimeoutError` 的别名。本机是 3.9.6。

仓库里三处 `except TimeoutError` 因此**全是死代码**：

| 位置 | 设计意图 | 3.9 上的实际行为 |
|---|---|---|
| `mj/api.py` `request()` | 超时即关连接、立刻抛出，不重试 | 落进 `except (HTTPException, OSError)` 重试分支 |
| `mj/bot.py` `_fetch_snapshot()` | `timeout=2.0` 快速失败，返回 `(None, None)` | 同上，2 秒变成 8 次重试 |
| `mj/bot.py` action 提交 | 超时即记异常窗口、跳过本窗口 | 同上 |

放大倍数：

- `state()` 用 `retries=8` → 单次调用最坏阻塞 **8 × timeout**（默认 35 秒时 ≈ 280 秒）
- `action()` 用 `retries=2` → 最坏 **3 × 35 = 105 秒**，而响应窗口只有约 2 秒
- 连着两三次即可解释观测到的 676~997 秒

**尚未完全解释的部分（诚实记录）：** 上述放大最多解释到 ~280 秒/次。
观测到的 676~997 秒需要 2~3 次连续触发，或存在第二个因素
（候选：`mj/bot.py:12` 的 `gc.disable()` 与第 1 轮扩大的 `lru_cache` 叠加导致内存压力）。
**没有直接证据，不要当成结论。**

## 3. 修复

三处统一改为 `except (TimeoutError, socket.timeout)`。在 3.10+ 上
`socket.timeout is TimeoutError`，元组写法无副作用，版本可移植。

新增 `tests/test_socket_timeout_gate.py`（4 条）锁死：

- socket 超时只尝试 **1 次**就抛出，不被 `retries` 放大（state / action 两条路径各一条）
- **非超时**的 `OSError` 仍然按 `retries` 重试——本次修复不得收窄它

## 4. 上线后怎么验

跑下一批房之后重跑本文件第 1 节的表。验收：

- **每个房间的 `discard` 超时 < 50**（健康房实测 1~45，坏房 675/738）
- **"我方弃牌中由服务端代打"的比例 < 10%**
- 决策日志中不再出现 ≥60 秒的整进程静默

## 5. 回滚

把三处改回 `except TimeoutError:` 并删除 `import socket`。
回滚会让本文件描述的停滞重新出现。
