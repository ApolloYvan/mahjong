## 0. 一句话结论

**垫底的首要原因是"胡牌频率显著低于随机基线"，而胡牌频率的损失高度集中在一个可定位的策略缺陷上：门清（无副露）局面下，`route_shanten = min(标准向听, 七对向听)` 这一分层口径让七对路线接管了弃牌选择。**
一旦某局我们在门清阶段有 6 手以上被七对路线领跑，该局胜率从 25.1% 塌缩到 1.7%，每局净分从 -0.05 掉到 -5.63。这类局占 7.7%，单项解释了总亏损的约 48%。

### 1.2 计分模型（从 1669 个非流局牌局逐条反推，**无一例外**）

- 闲家胡：胡家 `+10×fan`，**庄家 `-8×fan`**，另两闲各 `-1×fan`

- **胜者成为下一局庄家**（1672 局逐局验证）

**架构含义（此前文档未写明，但决定一切）**：庄家位是一个 8 倍杠杆位。闲家不胡只付 1×fan，庄家不胡要付 8×fan。而庄位由"上一局谁胡"决定 —— 所以**胡牌频率是一个自我强化的正反馈变量**，分数对胜率是强凸的。任何"稳健少输"的目标函数在这个规则下都是错的。

## 3. 主因定位：门清局面下七对路线劫持弃牌策略（P0）

### 3.1 代码机制

`mj/shanten.py::route_shanten()`：
```python
def route_shanten(counts, meld_groups=0):
    std = shanten(counts, meld_groups)
    if meld_groups:
        return std
    return min(std, pair_shanten(counts))     # ← 只在 meld_groups == 0 时启用
```
`mj/strategy.py::choose_discard()` 与 `mj/ev.py::choose_route_discard()` 都先用 `route_shanten` 做**硬分层**（只保留最小值那一档），再在档内用 `_discard_score` / `route_value` 排序。而 `_discard_score`/`route_value` 中的 `pair_count×25`、`b_progress=180`、`baohua_ticket=800`、`pair_route_bonus = 600×(3-pair_shanten)`、`seven_pairs_route=400×(pairs-5)` **同样只在 `meld_groups == 0` 时生效**。

**即：整套七对偏好只在门清时打开，一旦有任何副露就整体关闭。这在我们自己的代码里构成了一个天然对照实验。**

### 3.6 这笔交易的收益端：几乎不存在

5. **财神手牌的计算延迟是否直接导致了超时** —— 相关性明确（2 财神时 p99 339 ms、max 827 ms），但未做端到端归因实验。
6. **`piao` / 弃白续飘路径** —— 1672 局中 `piao_attempt` 记录为 **0**，`hu_strategy.choose_hu_or_piao` 的续飘分支在生产中**从未触发过**。因此 2026-09-22 对 `success_floor 0.5→0.3 / fail_cost 4.0→1.0` 的调整**既没有被验证也没有造成损害，是一次零效果改动**。全场 44 次弃财神中我们占 17 次（最多），但 fan≥2 主要来自爆头而非财飘。

## 8. 离线 Arena 的有效性裁决

### 8.1 自我声明的能力边界（`mj/arena.py::RULE_COVERAGE`）

`gang: False`、`catch_play_circle: False`、`chain_piao: "partial"`。

### 8.2 实测（本轮亲自跑）

`SeatStrategy('base','real')` 四座自博弈，150 手：

| 指标 | Arena | 真实 21 房 | 判定 |
|---|---|---|---|
| 流局率 | 0.000 | 0.0018 | 可接受 |
| fan=1 | 85.3% | 73.8% | — |
| fan≥2 | **14.7%** | **26.2%** | **少产出 44% 的大牌** |
| 单手耗时 | **4.4 s** | — | 见 §8.4 |

### 8.3 哪些模拟结果**无效**

1. **任何经由 `compare()` / `run_session()` 得到的结论全部无效**：该函数自己的 docstring 已标注 `[LEGACY / 非官方评测结果]`（A 恒坐 0/1 号位、B 恒坐 2/3 号位、全程共用一个 `random.Random`、跨批不重置）。**`tools/baohua_experiment.py` 和 `tools/slow1_experiment.py` 都调用 `compare()`**，因此关于"豪华门票权重"和"slow1"的历史结论**不构成 A/B 证据**。
2. **所有关于"七对 / 豪华门票 / 弃牌权重"的 arena 结论，对本报告的 P0 无判别力**：arena 是**同策略自博弈**，四家跑同一套弃牌函数。P0 是一个**相对速度**缺陷 —— 自博弈中四家被同等拖慢，净分差恒为 0。**Arena 在结构上不可能发现也不可能证伪 P0。**
3. **关于杠、抓打圈、财飘阈值的任何 arena 结论无效**：这三条规则在 `play_hand()` 里根本没实现（`gang=False`、`catch_play_circle=False`），`chain_piao` 只模拟"摸白后主动续飘"这一条路径，且不模拟抓打圈对其余三家的限制 —— 而生产中该路径触发次数为 0。
4. **fan 分布失真**：arena 少产出 44% 的 fan≥2 手牌，任何"牌值 vs 速度"的权衡结论都被系统性地推向了"速度不值钱"的一侧。

### 8.4 哪些还能用

- **可以用作硬规则回归护栏**：自摸制、吃碰优先级、财神不可吃碰、两摊吃上限这四条有实现且有测试。
- **不能用作策略 A/B 的裁决器**。
- 即便修好上述问题，功效也不够：4.4 s/手 × 检测 +0.5 分/局所需的 ~9,400 手/臂 ≈ **11.5 小时 CPU/臂**。

**裁决：本轮的 P0/P1/P2 三个方向，一个都不能靠现有 arena 验收。验收必须走"离线日志重放（机制指标）+ 真实对战（结果指标）"两级。**

## 9. 需要多少局真实对战才能验证

实测方差（21 房 / 1672 局）：**每局得分 sd = 12.24**；**每房（80 局）得分 sd = 112.8**。

| 目标效应 | 单侧检验 vs 固定历史基线（α=0.05, power=0.8） |
|---|---|
| +0.4 分/局 | 5,788 局 ≈ **72 房** |
| +0.6 分/局 | 2,572 局 ≈ **32 房** |
| +0.8 分/局 | 1,447 局 ≈ **18 房** |
| 胜率 20.7% → 23.5% | 3,418 局 ≈ **43 房** |
| 胜率 20.7% → 25.0% | 1,486 局 ≈ **19 房** |

**结论：用"总分"当第一道验收门是错的** —— 我们预期的效应量（+0.2~0.3 分/局）需要 100 房以上才能测出来，那是几十小时的对战。

**必须改用两级验收**：

- **第一级（机制指标，几乎无噪声，离线即可）**：改造后重放历史 1567 局，统计"门清阶段七对路线领跑 ≥6 手"的局占比。当前 **7.7%（121/1567）**。这是策略的确定性属性，**1 房即可判定，无需统计检验**。
- **第二级（子群结果指标）**：只看那些按旧口径会落入"6+"桶的局。旧值 **1.7% 胜率（2/121）**。这个基线极端到离谱，**5 房（400 局，其中约 30 局落入该子群）就能看出方向**。
- **第三级（总体结果指标）**：15–20 房（1200–1600 局）读总体胜率与分/局，作为**方向性确认而非证明**（该样本量只有能力检出 ≥+0.7 分/局的效应，必须如实声明）。

## 10. 优先级裁决（最多 3 个方向）

### P0 —— 收敛弃牌目标函数：七对路线降级为"严格优势才走"
- **证据**：§3（全部四条独立证据链）
- **预期收益**：**+0.20 ~ +0.28 分/局**（保守），相当于 +0.7 ~ +1.0 胜率点
- **风险**：可能误伤真正的七对牌（起手 5 对以上）。护栏见实施 prompt。

### P1 —— 在线存活与强制弃牌风暴护栏
- **证据**：§4（一次进程死亡 = -220 分；2+ 强制弃牌的局胜率 1.8%）
- **预期收益**：**+0.13 ~ +0.20 分/局**（消除 132 局的降级）
- **风险**：极低，纯运维加固，不碰策略。

### P2 —— 响应窗口延迟预算（抢回 14.5% 的合法碰 / 100% 的合法明杠）
- **证据**：§5（179 次合法碰 + 13 次明杠因超时丢失；财神手牌 `combined_route` 慢 1200 倍）
- **预期收益**：**+0.05 ~ +0.10 分/局**
- **风险**：中（涉及缓存/预计算，可能引入状态不一致）。**必须排在 P0/P1 之后**。

### 明确**不做**的事（本轮）
- 不动比赛协议、state/action 调度、胡牌判定（§6 已证明正确）
- 不动防守惩罚 `mj/defense.py`（§6 已证明喂牌率优于中位）
- 不动 `hu_strategy` 的财飘阈值（§7.6：生产触发 0 次，改了等于没改）
- 不重建 arena（§8：即使重建也验不了 P0，投入产出比最差）

## 11. 成功 / 失败的判定标准

### 判定改造成功
1. 机制指标：离线重放历史 1567 局，"七对领跑 ≥6 手"的局从 **7.7% 降到 < 2%**；
2. 且 "七对领跑 0 手" 的局占比**不下降超过 3 个百分点**（证明没有把七对整个砍掉换成别的畸形）；
3. 真实对战 15 房后：总体胜率 **≥ 23.0%**，分/局 **≥ -0.3**；
4. 旧口径"6+"子群的胜率从 **1.7% 升到 ≥ 12%**；
5. 房间级垫底率从 **47.6% 降到 ≤ 30%**。

### 判定假设被否定（必须回滚）
1. 机制指标达标（<2%），但 15 房后总体胜率 **仍 ≤ 21.5%** 且分/局 **≤ -0.8** → 七对路线不是主因，`route_shanten` 分层口径无罪，必须回滚并把调查转向"听牌后转化率"（§7.2）；
2. 或者：门清局胜率没有上升（仍 ≤ 14%）而有副露局胜率下降 ≥ 3 点 → 改动产生了跨路线的副作用，立即回滚；
3. 或者：出现任何 `route_shanten` 相关的 409 / 非法动作回归 → 立即回滚。

### 中性（不足以判定）
15 房后胜率落在 21.5% – 23.0% 之间 → 样本不足以裁决，继续采样到 32 房再读。**不得在这个区间里宣称成功。**

## 12. 给后续所有人的三条纪律

1. **不要再用 arena 的数字论证策略**。§8 已裁定其对本类问题无判别力。
2. **不要再用"样本少"解释失败**。1672 局、z=-4.35、70 局 0 胜 —— 数据早就够了，缺的是正确的分层。
3. **任何策略结论都必须先跑"机制指标 + 起手向听分层"两道控制**。§3.4 显示，不控制起手向听的任何横向比较都可能被牌运翻转；而 §1.3 显示，`start_hands` 可见的那 237 局是**短局偏差样本**，不能当随机样本用。
