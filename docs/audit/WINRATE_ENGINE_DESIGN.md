## 0. 本轮最重要的产出不是引擎，是评测台

### 0.1 一个被 bug 掩盖了一整天的事实：全部 1680 局都能完美重放

`/tmp/mjaudit/replay.py::merge_rounds` 有一处 bug：

```python
if b.get('start_hands'): d['start_hands'] = b['start_hands']
```

`start_hands` 缺失时的取值是 `[None, None, None, None]`——**在 Python 里是真值**。
所以一局的多个分页块中，只要后面有一个空块，就会把前面那个带真实手牌的块覆盖掉。

修正为 `if sh and all(sh):` 之后：

| | 修正前 | 修正后 |
|---|---|---|
| 可重放局数 | 237 / 1680 | **1680 / 1680** |
| 重放失败 | 1443 | **0** |

这直接推翻了审计报告 §1.3 里"揭示手牌的 237 局是系统性短局、不是随机子样本"
那条限制声明——它从来不是数据限制，是我的解析 bug。四家起手牌、每一次摸牌、
每一次吃碰杠，全部 1680 局都是完全信息。

### 0.2 由此得到的离线反事实评测台

`tile_drawn` 事件按 `seq` 排序就是**牌墙顺序**。在"不吃碰、只摸打"的约束下，
改变我们的弃牌**不会改变我们摸到的牌**（牌墙顺序与行动顺序都不变）。
于是可以做严格的配对比较：

```
race(起手牌, 该座位实际摸牌序列, 策略) -> (第几次摸牌自摸成和, 番)
```

两个策略看到**完全相同**的输入，是配对实验，功效极高。

| | 线上 30 房实测 | 本评测台 |
|---|---|---|
| 单轮耗时 | ≈ 7 小时 | **≈ 100 秒**（1672 局，8 进程，59 ms/局） |
| 网络请求 | 有 | 无 |
| 迭代成本 | 一天 2-3 次 | 一天几十次 |

**这是能在 10/8 冻结前把引擎调出来的唯一原因。** 没有它，15 天最多试 3 个版本。

### 0.3 评测台的已知局限（必须写在每一份用它出的结论旁边）

1. **不含吃碰杠。** race 只模拟摸打。历史上我们 1281 次吃、841 次碰，
   这些路径被排除。所以 race 的**绝对**胜率低于实际（15.0% vs 同子集实际 16.7%），
   只能用于**策略间相对比较**，不能当作线上胜率预测。
2. **对手被冻结。** 对手不会因为我们换了打法而改变行为；我们也不会因此
   被对手吃碰。所以它衡量的是"同样的牌，我们自己能不能打得更快"，
   不是"这套打法在真实对抗里的表现"。
3. **被历史局长截断。** 一局在第 20 次摸牌被对手胡掉，我们就只有那些牌。
   这是保守的——它不会高估我们。

4. **忽略动作链与抓打圈。** race 传 `chain_count=0`，也不模拟白板被打出后的
   抓打圈。所以 race 的平均番低于实际（实测 1.04 vs 实际 1.295）。
   对策略间比较无影响（两边都一样），但不要拿 race 的番数当真实番数。
5. **规则核验**：这 21 个房间的决策日志里 `rules` 全部是空 `{}`，
   即「有财必靠」未启用。所以 race 传 `rules={}` 是忠实的，不是简化。

档 2 / 档 3 的线上验证**不能**被这个评测台取代，它只是把"上线前的候选数量"
从 1 个变成 20 个。

## 1. 胜率曲面：经验证据

样本：21 个房间 / 210 局游戏 / 1672 局牌 / **14171 条我方弃牌决策**
（此前审计用的 7727 条是日志截断造成的，本轮已重抽）。

`s` = 生效路线向听（第 1 轮修复后的口径）；`k` = 我方剩余摸牌数 = `(wall_remaining − 20) / 4`。
`wall_remaining` 的实测最小值正好是 **20**，最大 **83**，一局最多 **63** 次摸牌
——与官方"最后 10 墩保留不摸"完全吻合（83 − 20 = 63）。

### 1.1 P(本局我方胜) 按 (向听, 剩余摸牌)

| s \ 剩余摸牌 | 0–4 | 4–8 | 8–12 | 12+ |
|---|---|---|---|---|
| **0（听牌）** | 16.1% (137) | 23.3% (1065) | 33.2% (2138) | **54.7%** (521) |
| **1** | 9.1% (22) | 6.4% (327) | 13.8% (1930) | 30.2% (1535) |
| **2** | – (1) | 9.3% (75) | 7.7% (861) | 20.6% (2054) |
| **3** | – (1) | – (14) | 4.5% (223) | 14.9% (1770) |
| **4** | – (1) | 0.0% (21) | 2.2% (135) | 8.7% (922) |
| **5+** | – (2) | – (5) | 6.8% (59) | 5.1% (352) |

**这张表是整个第 2 阶段的依据。** 读出来的第一件事：

> **一步向听的边际价值随剩余摸牌数剧烈变化。**
> 剩 12+ 摸时，s=2→1 值 +9.6pp、s=1→0 值 +24.5pp；
> 剩 4–8 摸时，s=2→1 值 **−2.9pp（已经是噪声）**，而 s=1→0 仍值 +16.9pp。

也就是说，牌局后段，**除了听牌以外的任何向听改善都不值钱**。
一手剩 5 次摸牌还在 2 向听的牌，已经基本死了，不该再为"进一步"付任何代价。

而现在的 `strategy.choose_discard` / `ev.choose_route_discard`
**签名里根本没有 `wall_remaining`**——第 5 巡和第 15 巡打得一模一样。
这是目前为止唯一一条"代码结构上不可能表达正确策略"的缺陷。

### 1.2 财神是压倒性的单一变量

| 手中财神数 | P(本局我方胜) | n |
|---|---|---|
| 0 | 8.7% | 8193 |
| 1 | **31.1%** | 5019 |
| 2 | **62.5%** | 873 |
| 3 | 84.9% | 86 |

每多一张财神约 **3.6 倍**。任何不把财神数放进价值函数的模型都是错的。

推论：`discard_joker_soft = −800` 这个量级没有意义——但实测我们
**14171 次弃牌里只弃过 1 次白板**，所以这不是一个真实存在的漏洞，
只是一个数值上不诚实的常数。不要为它单独开一轮。

### 1.3 一条被我自己证伪的假设（记录在案）

初看数据时（剩 8+ 摸）：

| | 进张 0–3 | 4–7 | 8–11 | 12–15 | 16+ |
|---|---|---|---|---|---|
| s=0 | 21.0% | 46.4% | 65.7% | – | 63.6% |
| s=1 | 8.4% | 16.0% | 23.3% | **45.3%** | **69.4%** |

看上去是决定性的跨层倒挂：**1 向听带 12+ 进张（45.3%）打赢听牌带 ≤3 进张（21.0%）**，
若成立就直接否定"先按向听分层再打分"这个两段式架构本身。

**按财神数分层 + 按局聚类自助法之后，它不成立：**

```
A = s0 且进张≤3 : n=1183  455 局  21.0%
B = s1 且进张≥12: n= 453  250 局  47.9%
分层后差异 (B−A) = +2.1 pp
聚类自助 95% CI = [−7.5, +14.3] pp     P(差>0) = 0.617
```

原始那个 21.0% vs 47.9% 的鸿沟**几乎全部是财神构成造成的**：
s0/进张≤3 的手里有 72%（847/1183）一张财神都没有，而 s1/进张≥12 的手财神很富。

**结论：两段式架构没有被这份证据证伪。** 引擎的理由不是"分层错了"，
而是 §1.1 的"分层的阈值应该随剩余摸牌数移动，而代码根本看不到剩余摸牌数"。
这个区别决定了改造的范围——前者要推倒重写，后者是在现有结构上接一个参数。

## 1.4 缺口的位置结构：越晚行动，我们越差（新发现，2026-09-23）

按"相对庄家的座位"（0 = 我们坐庄，3 = 我们在庄家上家、每圈最后摸）拆分，
并与**同一位置上的其他三家**（同一批牌局里坐同样位置的对手）逐位置对比：

| 相对位置 | 我们 | 同位置其他三家 | 差 | z |
|---|---|---|---|---|
| 0（庄） | 26.1% (n=368) | 28.6% (n=1301) | −2.5 pp | −0.96 |
| 1 | 21.1% (n=402) | 26.9% (n=1267) | −5.8 pp | **−2.42** |
| 2 | 20.7% (n=430) | 25.1% (n=1239) | −4.4 pp | −1.91 |
| 3（最后摸） | **16.2%** (n=469) | 24.9% (n=1200) | **−8.7 pp** | **−4.13** |

单调梯度。关键对比：

> 从位置 0 到位置 3，**全场只掉 3.7 pp，我们掉 9.9 pp**——
> 位置劣势对我们的伤害是全场平均的 **2.7 倍**。

位置越靠后 = 本局能摸到的牌越少。"牌少的时候受伤更重"是**速度慢**的典型
signature：如果我们成和所需的摸牌次数比对手多，那么被截断时吃亏的概率就更高。

同时注意：`mj/bot.py` 里 `use_route = True` **只在庄家时打开**，
即位置 0 走 `ev.choose_route_discard`，位置 1/2/3 走 `strategy.choose_discard`。
唯一与全场持平的位置，恰好是唯一不走 `strategy.choose_discard` 的位置。

**这是相关，不是因果**——位置 0 同时还是"庄家倍率更高、先摸"的位置。
不要据此直接把闲家也切到 route。正确的做法是在评测台上把两条路径
**在同一批牌上**跑一遍配对比较（`POLICY=base` vs `POLICY=route`），
那个比较没有位置混淆。**结果未出之前，这条只是待验证假设。**

## 1.5 胜一局的真实价值比直接得分高 7%

赢家成为下一局的庄家，而庄家是 8 倍杠杆位（庄胡 +24×番 / 闲胡 +10×番；
闲家胡时庄付 8×番、其余各付 1×番）。实测这个传导：

| 本局结果 | 下一局我方平均分 | 下一局我方胜率 | n |
|---|---|---|---|
| 胜 | **+0.51** | 26.3% | 316 |
| 负 | **−1.15** | 19.2% | 1137 |

**一次胜利在下一局还额外值 +1.66 分。** 加上即时收益（平均 +18.09）
与避免的支出（平均 6.0），胜率这个杠杆的真实价位是：

> **胜率每 +1 个百分点 ≈ +0.257 分/局**（此前只算即时项时估的是 0.24）

我们 4.3 pp 的胜率缺口 ≈ **−1.10 分/局**，而实测缺口是 −0.836 分/局。
胜率仍然解释了全部缺口并略有富余——**不需要再去找第二个主因**。

跨玩家回归：

```

即   胜率每 +1 个百分点  =>  +0.255 分/局
```

**R² = 0.943。** 番型、防守、吃碰次数、弃牌安全度……所有其他维度加起来
只能解释 6% 的分差。这和 §1.5 从赔付结构独立推出的 +0.257 分/pp 几乎完全一致
——两条互不依赖的路径得到同一个数，这个价值模型可以信。

**目标刻度（唯一需要记住的三个数）：**

| 目标 | 需要的胜率 | 相对现在 |
|---|---|---|
| 分数打平（0 分/局） | **25.4%** | **+4.7 pp** |
| +1.0 分/局 | 29.4% | +8.7 pp |
| 追平榜首 Astra-0 | 34.2% | +13.5 pp |

一个必须说清楚的保留：**榜首的数字本身很不精确。** Astra-0 只打了 160 局，
33.1% 的 95% 置信区间是 [25.8%, 40.4%]；我们打了 1669 局，20.7% 的区间只有
[18.7%, 22.6%]。也就是说"榜首真实水平"可能低到 26%。
**"打平" 这个目标有坚实的数据支撑；"夺冠需要 34.2%" 这个数不可靠，
不要拿它当工程目标。** 正确的做法是先打到 25–27%，再用新数据重新测量对手。

## 2. 目标函数

### 2.1 为什么可以只算进攻

平台规则：**只能自摸，没有点炮，没有抢杠胡**。
所以我们打出的牌**不会**改变"别人胡牌时我们付多少"。它只通过
"对手能不能吃碰我们这张"影响对手速度，是二阶项。

一阶项是纯进攻。目标函数：

```
EV(手牌 H, 剩余摸牌 k) = P_win(H, k) × ( 座位倍率 × E[番 | 胡] + C )
```

- 座位倍率 = 24（庄）/ 10（闲）
- `C` = 我们不胡时的平均支出（实测 ≈ 6.0），因为胡牌同时**避免**了这笔支出

由此得到两个杠杆的实际价位（闲家基准）：

- **胜率 1 个百分点 ≈ 0.24 分/局**
- **番/胡 +0.1 ≈ 0.21 分/局**（在 20.7% 胜率下）

我们的缺口是 **−0.836 分/局**，胜率缺口 4.3pp ≈ **−1.03 分/局**。
两者量级吻合——**胜率仍然是主矛盾，番是次要但不可忽略的第二杠杆**。

### 2.2 E[番 | 胡] 的可控部分只有爆头

1672 局全部 343+ 次胡牌里，fan≥2 的 438 次中 **394 次（90%）带爆头**，
**豪华七对 0 次**。而当前代码用 `baohua_ticket = 800` 去保护一张从未兑现的彩票。

> 待补：爆头的可预测性拟合（P(爆头 | 手牌形态)）——见 §5 未完成项。

## 3. 接口改造（给实施方的最小面）

```python
# 现在
choose_discard(tiles, meld_groups=0, chain_count=0, piao=0, rules=None, visible=None)

choose_discard(tiles, meld_groups=0, chain_count=0, piao=0, rules=None, visible=None,
```
