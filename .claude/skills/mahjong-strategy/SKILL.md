# 杭州麻将策略底座

> 截至 2026-09-24 全部经实盘数据验证。**标 ⚠️ 的是未验证假设，不要当依据用。**
> 目标：进 4 强。不是打平。

## 1. 番数算式（硬规则，不是估计）

```
番数 = 分支因子 × 2^链次数 × (合计==4 ? 2 : 1) × (爆头 ? 2 : 1)

分支因子：平胡 1、七对 2（豪华七对更高）
链次数  ：财飘次数，封顶 3
合计    ：counts[白] + 已飘出白板数        ← 「4个白板」的判据就是 合计 == 4
爆头    ：13 张手牌摸任意合法牌都能胡
赔付    ：闲家 +10×番，庄家 +24×番
```

两条独立路线都正好收敛到 32 番，14 局实盘无例外：

```
平胡 × 2³(三财飘) × 2(4白板) × 2(爆头) = 32
七对 × 2²(双财飘) × 2(4白板) × 2(爆头) = 32
```

**从分数反推番数**：`番 = 得分 / (庄家 ? 24 : 10)`。注意 `tools/fan_analysis.py` 的映射只到 8 番，
32 番的手会被丢掉或错分——它低估顶端，别拿它下"没有大牌"的结论。

## 2. 财飘三段式（14/14 局实盘一致）

赢家在**最后收手那一摸**全部满足 `链次数 + 手中白板 == 4`。完整路线：

```
① 合计 < 4   → 不胡。摸到白板就飘掉（链+1、手中白不变、合计+1），否则正常做牌保爆头
② 合计 == 4  → 用手里的白板继续飘，一路飘到 链 == 3（封顶）
③ 链 == 3    → 立刻胡
```

最赤裸的一局（a_9d9461aa00a5 r4 座3，32番）连续**四次放弃爆头自摸**只为等第 4 张白板：

```
seq841/865/889/913  链0 手中白3 合计3 爆头   ← 四次不胡
seq921              链0 手中白4 合计4 爆头   ← 第4张到手才动
seq933/945/957      链1→2→3                  ← 飘满收手 = 32番
```

**配套技巧**：用吃/碰把「财神撑着的组」换成真组，把财神解放出去飘。每换一次，多一个 ×2。

**已验证的飘牌门槛**（n=62 真财飘）：

| 判据 | n | 最终胡牌 | 平均番 |
|---|---|---|---|
| 打掉这张财神后**仍然爆头** | 46 | 42 = **91.3%** | 4.29 |
| 打掉后不再爆头 | 16 | 5 = 31.2% | 1.00 |

所以 `_piao_candidate` 的唯一硬判据就是"打掉后仍爆头"。注意 91.3% 是**单步**成功率，
用在多步上必须按剩余步数复利（`rate ** remaining_chain`），否则剩 3 步时把乐观算了三遍。
另：真财飘里 60% 飘的是**手里原有**的财神，不是刚摸到的——只处理"刚摸到"会漏掉大半机会。

🚫 **段①的「弃胡等白板」已被证伪，不要照抄。** 全语料 1018 个对局文件、2006 个
「曾经爆头」的座位×局样本（`tools/joker4_funnel.py`）：

| 首次爆头时的合计 | 对手手数 | 后来凑到合计4 | 等待的 EV | 立刻胡 |
|---|---|---|---|---|
| 3（差一张白板） | 146 | **1 次 = 0.7%** | 0.007 × 8.00 = **0.056 番** | **2.00 番** |

**等待只值立刻胡的 1/36。** 整个语料里「首次爆头时合计已达4」只有 4 例 / 2006 = 0.2%——
牌里总共只有 4 张白板，要全部过一遍自己的手，这是彩票不是路线。

那 14 局 32 番回放全是 `data/replay.jsonl`（荣耀回放，按番数筛过的赢家集），
**它们就是那 0.7% 的中奖者**。14/14 的一致性是抽样造成的，不是策略造成的。

👉 **`mj/hu_strategy.py` 不需要为此修改。爆头之后就该胡。**

## 2b. 番数差距的真正位置（同一份漏斗数据）

```
首爆头合计   对手手数  胡牌率  平均番  │  我们手数  胡牌率  平均番
1           804    82.2%   2.21   │   171    77.8%   2.11
2           724    85.8%   2.25   │   136    83.1%   2.07
3           146    88.4%   2.43   │    21   100.0%   2.19
```

**爆头之后我们没问题**（转化率差 3~4pp，平均番差 0.1~0.2，合计3 时我们 21/21 全胡）。
**问题在到不了爆头：**

```
对手爆头样本 1678（3 家）  我们 328（1 家）
对手爆头率 / 我们爆头率 = 1678 / (3 × 328) = 1.71 倍     ← 不依赖局数，直接可算
```

把 番/胡 拆开（爆头手 ~2.1 番、非爆头手 ~1.03 番）：

```
我们  胡牌 1999 次，其中爆头 267 次 = 13.4%   →  0.134×2.10 + 0.866×1.027 = 1.170 ✓
对手  胡牌 5643 次，其中爆头 1415 次 = 25.1%  →  0.251×2.25 + 0.749×0.995 = 1.310 ✓
```

**非爆头的手我们和对手番数一样（都≈1.0，就是平胡1番）。整个 1.17 vs 1.31 的差距
100% 来自「胡牌里爆头占比」13.4% vs 25.1%。**

要把 番/胡 做到 1.253（当前胜率下的前4线）：

```
p × 2.10 + (1−p) × 1.027 = 1.253  →  p = 21.1%
```

**目标：爆头占胡牌比例 13.4% → 21.1%。对手已经是 25.1%，所以这个目标低于对手现状，可达。**

**唯一的施力点是「怎么把手做成爆头」**，不是胡/飘的取舍：
- `mj/responses.py`：吃碰是造爆头的主要手段。实测吃碰后听口 我们 14.11→22.82 / 爆头率 2.1%→13.2%；
  对手 14.13→30.46 / 1.2%→22.8%。**同样的起点，对手每一口吃碰的听口增益是我们的近两倍——
  他们挑着吃，我们来者不拒。** 要改的是"吃哪一口"的选择，不是门禁松紧。
- `mj/ev.py` / `mj/shanten.py`：弃牌评分里缺少"往爆头方向收敛"的导向。

### 爆头率按 (手上财神数 × 副露组数) 拆分（tools/joker_playbook.py）

```
               1白0露  1白1露  1白2露  2白0露  2白1露  2白2露    总爆头
歪比巴卜肉蛋葱鸡    17%    16%    45%    80%    79%    81%     38.3%
腾蛇-0638        33%    30%    54%     -     77%    62%     43.1%
两脚离地了         11%    26%    57%     -     64%     -      44.2%
双白平胡           -      7%    56%     -     38%    79%     35.2%
重生之我是雀神(我们)  2%     1%    19%     2%    12%    39%     13.4%
```

三条硬结论：

1. **`0白` 各格全场都是 0%——没有财神就不可能爆头。**
2. **我们在每一格都是倍数级落后**（1白1露 1% vs 7~30%、2白0露 2% vs 80%）。
   这是**条件**爆头率的差距，不是"我们财神少/副露少"的构成差距。同样的原料，产出差一个数量级。
3. **所有人的爆头率都随副露数单调上升。** 吃碰是造爆头的**手段**，不是它的对立面。
   （`joker_playbook.py` 自己的注释猜"高手是留着财神不用、不靠吃碰抢速度"——**猜反了**，
   高手的优势恰恰集中在"财神多 + 副露多"。）

**`2白0露`（2张财神、门清）我们 2% vs 歪比巴卜 80%，40 倍，且完全没有吃碰参与——
这一格只能靠 `mj/ev.py` / `mj/joker_ev.py` 的弃牌评分解决。**

## 3. 抓打圈（catch_play）

一次财飘后全桌必须"摸什么打什么"。实测 14 局共 156 次抓打圈弃牌，期间：

```
chi 1   peng 0   gang 1        ← 吃碰实质上死亡
round_ended 15/15 在 catch_play=true 期间   ← 胡是合法的
```

**结论：抓打圈不禁胡**（否则标志位到本局结束不清，就没人能胡完这局）。
`mj/bot.py` 里 `can_hu` 排在 `catch_restricted` 之前**不是 bug**，别去调它。
我们的 `hu` 在一整天日志里只被拒过 3 次。

但吃碰要守：`catch_restricted = god.catch_play and god.god_discarder_seat != seat`。

## 4. 价值模型与当前坐标

46 名玩家、两个变量，R²=0.907：

```
分/局 = −9.274 + 23.111×胜率 + 2.721×(番/胡)

胜率 +1pp   = +0.231 分/局      可达区间 19.2%~37.2%（18.0pp → 4.17 分/局）
番/胡 +0.1  = +0.272 分/局      可达区间 1.08~1.67（0.59 → 1.61 分/局）
打平 ≈ 25.4% 胜率      进4强 ≈ 27.5% 胜率 / +0.700 分/局
```

**当前状态（2026-09-24，38 房 2996 局）**：

```
胜率 28.4%  ✅ 已过前4线 27.5%          服务端代打 0.2%（超时问题已解决）
分/局 +0.171 ❌ 离 +0.700 差一大截
番/胡 1.17（n=1999）vs 对手 1.31（n=5643）
4番+  我们 0.60%  vs 对手 2.91%          ← 差 4.8 倍，整个差距就在这条尾巴上
```

⚠️ **均值骗人**：38 房里 **23 房是负分**，中位数房间 **−0.45 分/局**。整个 +0.171 靠 5 个房撑着，
其中两房胜率 60.3%/48.6%（z≈+7/+5，远超二项噪声）——那几桌对手弱，不是我们强。
典型桌上仍是 25~26%。

**所以现在的唯一杠杆是番数**：在 28.4% 胜率下，`番/胡 1.17 → 1.253` 就摸到前 4 线
（+0.53 分/局）。把 4番+ 从 0.60% 提到对手的 2.91% ≈ +0.069 番/胡，几乎正好是缺口。
**胜率已达标，停止投入。**

**大牌是做出来的，不是发出来的**：14 局 32 番的起手财神数分布 `{0张:4, 1张:6, 2张:3, 3张:2}`。

## 7. 研究纪律（血的教训）

1. **调权重全在噪声里。** 按 build_hash 切分真实对局，9 个代码版本没有一个显著优于其他。
   唯一被证据钉死的缺陷（摸财神拒胡 243:0）是靠"同一局面下我们做什么、对手做什么"找到的。
   **先找恒等于 0 / 方向反了的 bug，再谈调参。**
2. **赢家回放有 survivorship bias。** 失败的成本从不进入样本。14/14 看起来是铁证时最危险。
3. **小样本不要过度解读。** 周榜前列的人在本地语料里常常只有 3~7 场（z<2）。
   `--player` 盯人时先看局数，再看分歧率。
4. **决策环路里不放模型。** 两个理由：(a) 延迟——纯 Python 都曾经 14.8% 的碰牌窗口超时；
   (b) 我们的缺陷是"公式没吃透 / 动作空间缺分支"，不是拟合精度。
   `2³×2×2=32 所以要等第4张白板` 是算出来的，不是拟合出来的。
   要提策略上限就做**离线 rollout + 权重拟合**，把结果编译成权重表带进对局，延迟为零。
5. **不要让 agent 自动改策略跑实战循环。** 适应度函数看不见 survivorship bias。
   Agent 该做的是**并行探针**：多个假设同时验，各自只回报证据。

## 6b. 得分归因：差距在哪、不在哪（tools/score_attribution.py）

```
              收入/局   支出/局   净/局    每胡分数  1番收入占比  0露/1露/2露
腾蛇-0638      +8.078   −4.634  +3.443    22.9      36%      21/38/41
牛来           +7.118   −3.994  +3.125    19.6      67%      18/41/41
面包猪         +6.808   −4.158  +2.650    18.3      58%      18/41/41
歪比巴卜        +6.720   −4.358  +2.362    22.9      39%      16/33/51
Astra-0      +6.945   −4.665  +2.280    21.6      46%      18/35/47
两脚离地        +6.381   −4.266  +2.116    23.7      35%      16/40/44
我们(9272局)   +4.143   −4.600  −0.457    16.7      73%      15/28/57
```

**三条已经封死的结论，不要再回头查：**

1. **支出不是问题。** 我们 −4.600，高手区间 −3.99~−4.67，**我们在区间里**。
   杭州麻将只有自摸、没有点炮 → **这个游戏没有防守**，支出完全由对手决定。
   `分/局 = 收入 − 支出`，我们唯一能动的是收入 = 胜率 × 每胡分数。
2. **速度不是问题。** 快胡(≤8巡)收入占比 我们 63%，高手 56~69%，完全一样。
3. **庄位不是问题。** `tools/dealer_edge.py`：我们坐庄胡率 30.6% > 对手 28.6%，
   庄−闲 +7.7pp > 对手 +4.7pp。**但庄位上我们胡得更多却只赚 0.67 倍**（又是番数）。
   差距的 74% 在闲位（闲位占 75% 的局）。

**两条真问题：**

4. **每胡只值 16.7 分**（高手 18.3~23.7），**73% 的收入来自 1番牌，全场最高**
   （即便纯靠胜率的牛来也只有 67%）。
5. **1露 收入占比 28%（全场最低）、2露 57%（全场最高）。**
   高手是 1露/2露 均衡（38/41、41/41、33/51、35/47、40/44）。
   0露 我们 15% vs 高手 16~21%，差不多 → **不是"我们太爱吃碰"，是"第一口吃完
   手牌没变好，只好再吃第二口来救"**。直指 `claim_assessment` 的
   `first_meld_neutral_no_pair_route`（向听持平就放行首副露）。

**收入构成里两条并存的取胜路线**（不是只有一条）：
- 高胜率低番：面包猪 37.2%/18.3分、牛来 36.4%/19.6分（1番收入占 58~67%）
- 低胜率高番：两脚离地 26.9%（只比我们高 2.1pp）/23.7分，4番收入占 28%

## 6c. 离线 A/B（tools/weight_ab.py）

`mj/arena.py` 的 `run_arena()`：镜像配对座位 + 每手独立派生 seed + 95% CI，
**结论必须从 CI 边界推导**（代码注释原话：绝不允许根据单次 score_delta 的正负
宣称策略胜出）。

```bash
python3 tools/weight_ab.py --set baotou_all_wait=25000 baotou_wait_power=1 --batches 32
```

三个硬约束，每一条我都踩过：
- **`--batches` 必须是 16 的倍数**（SCHEDULE_PERIOD），否则直接 ValueError
- **policy 必须是 `current` + claims `real`**。`claims="all"` 是「无脑全吃碰」，
  **完全绕过 `choose_chi`/`claim_assessment`**，测吃碰改动时结果无效
- `run_arena` 自述 `official_fidelity=False`：**杠/抓打圈/连庄/漂分都没模拟**，
  所以它能回答"速度换番数划不划算"，**不能**回答财飘链相关的问题
